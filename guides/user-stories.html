User stories

MechaHarness acceptance paths are told as user stories: short scenes about what a product needs to do, written for readers who understand features but not code. Each story has a human narrative, an implementation section that traces library code fulfilling the feature, and a validation section that describes how the story is tested. Story text lives only in fixture story.json files. This guide is generated from those fixtures.

See the Cursor skill .cursor/skills/user-stories/SKILL.md when adding features: edit fixtures, regenerate this page, and keep twin copies of the same story id identical.

Personas

Nubble — operations / DevOps

Nubble keeps production and CI reliable. He cares about the right inference profile being loaded, cost and progress signals he can forward to billing or monitoring, and metrics that explain whether parallel work actually helped.

Fangore — application developer

Fangore builds product applications on MechaHarness. He cares about deny-by-default permissions, product rules that models cannot override, durable local plans that survive crashes, loops that stop when they are not making progress, and context that never silently drops mandatory requirements.

Taloneth — ML engineer

Taloneth owns judge contracts, adapter drift checks, and harness experiments. He cares about offline fixture batches, versioned recorded replies, honest shadow comparisons, validator qualification before promotion, research that rejects failing candidates, and decision exports that do not leak future outcomes.

Running the suite

Default CI runs every story offline (static fixture + cassettes) — no skips.

# CI / offline — all stories, zero skips
pytest -q tests/stories

# Full suite (unit + stories)
pytest -q

# Live OpenAI-compat — same tests, real HTTP
MECHA_STORY_BACKEND=live MECHA_STORY_MODEL=openai_compat/qwen3-30b-thinking \
  MECHA_BASE_URL=http://127.0.0.1:8000/v1 pytest -q tests/stories -k nubble_run_cost

# Live System One
MECHA_STORY_BACKEND=live MECHA_STORY_MODEL=systemone/laya \
  MECHA_JUDGE_BASE_URL=http://127.0.0.1:8009 pytest -q tests/stories -k refund_verdict

# Shorthand aliases (still dual-mode stories, not separate skipif modules)
MECHA_LIVE_JUNESPARK=1 MECHA_BASE_URL=… pytest -q tests/stories -k nubble_run_cost
MECHA_LIVE_QWEN=1 MECHA_BASE_URL=… pytest -q tests/stories -k nubble_run_cost
MECHA_LIVE_JUDGE=1 pytest -q tests/stories -k 'refund_verdict or systemone_cassette'

Behavior

Live parity is a mode of cassette-backed stories (for example nubble_run_cost_events, fangore_refund_verdict, taloneth_systemone_cassette), not a separate empty fixture. Flip MECHA_STORY_BACKEND=live to run the same request and expect files against a real endpoint.

nubble_lane_load_hint — Refuse work when the wrong inference profile is loaded

Nubble is on call when a refund-routing job fails on the local inference host. The job needs the judge profile, but an earlier experiment left the reason profile loaded instead. The harness must not fail with a vague error. It must tell him, in plain operator language, that this work needs the judge lane and which load command to run. Hosts supply a real environment via Config instead of NoOpInferenceEnvironment.

Covers: INF-02.

fangore_graph_executor — Run a local plan through an authorized graph executor

Fangore ships a host app with a produce → repair → consume plan. After linkage succeeds, the library must walk ready steps, refuse execution without an execute grant, retry transient failures, escalate when retries are exhausted, emit start and end telemetry, and finish the downstream consume step only after upstream success. Checkpointed plans from fangore_local_plan_resume stay durable; preflight failures are covered by fangore_graph_linkage_preflight. See inspiration requirements for authorized graph execution[7].

Implementation

GraphExecutor in mechaharness.graph_executor is a pyiv injectable: constructor takes EventLog, AccessControl, GraphNodeRunnerRegistry, GraphFailurePolicy, GraphEscalation, and LinkageResolver. Hosts register node runners by open kind string via MechaHarnessConfig.get_node_runner_registry(), override failure/escalation/linkage hooks, and grant core:graph.execute / core:graph.escalate. The executor emits core:graph_start / core:graph_end plus per-node events, checkpoints through GraphStore (with config fingerprint), and enforces per-runner grants.

Validation

Kind graph_executor_run → _run_graph_executor_run. Soft expects: denied without execute grant; ok status with consume sum; graph_start/graph_end present; flaky attempts before escalation. fangore_graph_linkage_preflight — Fail closed on missing graph linkage before work starts

Fangore composes a plan that still names a step the host has not wired, and another repeating step without a stop rule. The library must refuse those plans before any runner work starts, naming the missing edge so operators can fix wiring instead of debugging a mid-run crash. Complements fangore_graph_executor (authorized run once linkage is sound) and fangore_convergence_ceiling (budgets once a loop is allowed). Missing runners and missing stop contracts become structured UnsatisfiedEdge codes (no_runner, missing_stop_contract). GraphExecutor.run records linkage failure without invoking node handlers.

Validation
