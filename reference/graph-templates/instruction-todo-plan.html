Instruction todo plan (instruction_todo_plan)

Agentic Recipe. Classify the current instruction as a oneshot or an ordered todo list, refine the list for conflicts, freeze pre-list acceptance, execute each item with per-item verify, then check post-list acceptance so later steps have not undone earlier ones. Human calling refinement returns as generator advice_requested; answering restarts the plan with guidance_history.

Required guidance soft points are auto-queued at generator start. Optional guidance soft points are not auto-queued — local work returns request_guidance and DurableGraphGenerator._advance yields, then restarts after resume.

Failure escalate: restore → consolidated retry → guidance

When ProjectCodingLocalWork exhausts verify_runs repair rounds (or a work item fails), it escalates instead of failing immediately:

  1. Consolidate failure lines into one restore-and-finish brief (decompose_instructions_from_failures) — not one todo per verify line. The brief leads with fixed non-negotiables (no eval/exec/literal_eval, keep API shape) and includes the full goal text (not a short clip).

  2. Restore the coding workspace filesystem checkpoint (refreshed after each successful suite stage and at coding-burst start / success), then retry once in-process with that consolidated oneshot (decompose_auto_applied). Empty checkpoints never overwrite a non-empty workspace.

  3. If the retry still fails → yield advice_requested with context_version=decompose (proposed brief + failures).

  4. Driver answer (accept_proposed, revise text, or structured.instructions) restores the baseline again and restarts; clarification becomes the plan (list mode when multiple instructions are supplied).

  5. After a answered decompose, a further failure is terminal failed (no infinite yield loop).

write_file / verify also AST-refuse eval/exec/literal_eval cheats when stories ban them; repair bursts get the same semantic host-verify hints.

Linear story / CLI walks can set answer.on_decompose: accept_proposed so the durable instrumentor drains that escalate yield once without a second YAML step (MCP drivers still answer interactively when they omit the flag).
