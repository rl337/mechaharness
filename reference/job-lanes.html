Job lanes and JobLaneBroker

Lane-scoped run sequences, WalkBags, and authorized observe. Module target: mechaharness.job_lane_broker (shim-deprecate mechaharness.isolation.cross_task_isolation.CrossTaskIsolationGuard).

Stability: evolving (types + Config bind + CLI verbs + JL stories landed).

Mental model

A JobLane is a pipeline identity (cron, commit-triggered, or manual). Each execution is a run in that lane’s run sequence. The JobLaneBroker holds each run’s WalkBag and answers:

What were the exposed values (e.g. asset URLs) for lane X — latest, before time T, or run_id R — for caller lane Y?

Same lane → lineage allowed by default. Other lane → only if the publisher’s exposure policy and/or standing grants (or a one-shot handoff) permit it.

WalkBag

Per-run register file (in / out / ask / ans / acc / ctx / err). Typed values include FileArtifact (path or url). See mechaharness.walk_bag. The broker owns bags; nodes do not poke another run’s bag directly.

Exposure and grants

Layer

Role

Lane exposure

Publisher declares meta and each key: open, deny_all, or allow_lanes

Standing grant

Optional broker-level grant from lane A to lane B for keys/meta

observe checks publisher policy and caller identity (analogous to AccessControl checks).
