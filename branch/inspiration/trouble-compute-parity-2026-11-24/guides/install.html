Install & quick start

Get a local environment running and issue a first harness run.

Prerequisites

  • Python 3.9+

  • For real inference: a cloud API key or local OpenAI-compatible server. The mock quick start below needs neither.

Steps

From PyPI:

pip install mechaharness

Editable checkout:

python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,docs]"

Install pulls pyiv from PyPI (pyiv>=1.1.1). Docs: https://rl337.org/mechaharness/

Mock (no network)

mechaharness run "What is 2+2?" --backend mock --family pass_through --model mock

The mock backend echoes mock reply: <prompt>. Use this to verify EventLog + cost without a GPU.

Local LM Studio / Qwen

mechaharness run "Reply with the single word ok." \
  --backend lmstudio \
  --family pass_through \
  --model qwen/qwen3.6-35b-a3b

Default live story model for LM Studio-style Qwen is openai_compat/qwen-qwen3.6-35b-a3b. Offline CI uses the same story via cassette (no skip). Live reason filter:

MECHA_STORY_BACKEND=live MECHA_STORY_MODEL=openai_compat/qwen-qwen3.6-35b-a3b \
  MECHA_BASE_URL=http://127.0.0.1:1234/v1 \
  pytest -q tests/stories -k nubble_run_cost

For the full model-using live suite (reason + judge), set both MECHA_BASE_URL / MECHA_MODEL and MECHA_JUDGE_* — see User stories and Local OpenAI-compat.

List what is registered:

mechaharness backends
mechaharness families

Local LM Studio

mechaharness run "What is 2+2?" \
  --backend lmstudio \
  --family tool_loop \
  --model local-model

OpenAI

export MECHA_API_KEY=sk-...   # or OPENAI_API_KEY
mechaharness run "Hello" --backend openai --model gpt-6-luna

Cheap live story filter (cloud Luna; explicit opt-in only):

MECHA_LIVE_OPENAI=1 MECHA_MODEL=gpt-6-luna \
  pytest -q tests/stories -k nubble_run_cost

Default / static pytest never calls the cloud API (cassettes only). See Local OpenAI-compat for the cloud OpenAI section.

HTTP API

mechaharness serve --port 8080
curl -s http://127.0.0.1:8080/health

Verify

  • mechaharness version prints 0.1.0 (or current)

  • ./run_checks.sh passes from the repo root

  • ./containers/run-ci.sh passes in an Ubuntu 24.04 + Python 3.12 image (same as GitHub Actions)

  • /health returns {"status":"ok",...}

CI-like container

containers/ holds an Ubuntu 24.04 + Python 3.12 image that matches .github/workflows/ci.yml. It installs the checkout (pip install -e ".[dev]", including pyiv from PyPI) and runs ./run_checks.sh.

./containers/run-ci.sh

Pass extra arguments to run a command in that environment after install (./containers/run-ci.sh pytest -q tests/test_di.py).
