Trouble: distinguish coordination from extra inference compute

2026-11-24; TR-20261124-PACE; verification/evaluation/self-improvement; test_evaluation. Candidate acceptance extension, no production features.

Source dossier

Trouble 20 Nov post 2123839120854188303 links PACE repository, paper v2, 22 Nov (original 13 Nov). Read repository README and current paper abstract; repository includes code/pace, evidence contrast tables and reproduction scripts. Source defines greedy single pass, independent sampled baseline, resource-matched/shared ceiling and compute-cost frontier as four progressively more informative comparison classes. Six resource dimensions distinguish reasoning, tokens, cost, latency, sample count and system constraints. A directional comparison credits improvement against a baseline allowed at least the declared resources; an equal-or-cheaper baseline that matches or beats the candidate weakens a coordination claim. Incomparable vectors need explicit treatment, not scalar averaging. The paper’s revised abstract reports 53 of 123 positive greedy comparisons become nonpositive against sampled baselines. Shared-evidence controlled experiment finds no clear advantage of vanilla debate over an equal-token self-consistency frontier; split-evidence debate beats a lower-budget pool but remains below placebo and chance. These are source findings, not universal multi-agent conclusions or locally reproduced benchmarks. Source README and paper revision report slightly different aggregate descriptions; use pinned v2 for numerical claims. Do not import external datasets or executable agents without review.

Repo audit and fit

MechaHarness has run_parity.py (blob a012ba8baa5be99ff94ac4a8ddbf9b080cb597d7) implementing equality over max tokens, turns, sampling, tools, retry/stop, timeout and context limits (MH-MHRL-12; taloneth_insp_run_parity). This is constraint parity, not measured resource dominance. eval_trial.py already distinguishes scored trials and cost/latency, pass@k/pass^k; eval_matrix.py MH-MHRL-17 retains model/harness/task-family cell detail. research.py EXP-04 frozen protocol, budget, held-out gate and promotion. gastronomic comparison guide, gastronomic_comparison.py, and tests already compare matched budget/model across A/B, preserve token counts and do not auto-declare winner. Existing Fangore story fangore_gastronomic_comparison_trial is the most concrete extension point. No observed generic acceptance for independent sampled arm plus measured directional resource feasibility across coordination variants. Coverage C, not replacement of those APIs. Open PRs #58–60 cover authorization, prefix attribution and harness fidelity, not this comparison; June #29 already proposes matched workflow comparison, can consume the shared generic contract rather than duplicating it. No new June story in this pass.

MH-PACE-01 (provisional amendment): coordination benefit at declared resource parity

As a graph author experimenting with council/debate/fan-out recipes, I want an independent sampled baseline at a declared whole-task resource budget, so added compute is not mistaken for coordination benefit. Frozen task manifest, evaluator, base model, accessible evidence, seed panel, token/cost/latency/sample constraints and arm fingerprints. Arm A single pass; B independently sample same evidence and aggregate with a fixed predeclared rule; C communicate under the same resource ceiling; optional frontier of B sample budgets. Count coordinator, critic, repair, aggregation and retries; avoid counting cached tokens as zero resource by default; record actual usage and configured cap separately. Don’t use candidate to choose held-out examples or give it different evidence unless that is an explicitly separate experiment.

Proposed Fangore and library assertions:

  1. Synthetic scored fixture A=0.50, B=0.75, C=0.75 at equal actual declared token totals for B/C: improvement over A alone is not evidence of coordination benefit. A/B/C report links and evaluator fingerprint retained. Values illustrative only.

  2. Candidate higher success than cheaper B alone: no parity benefit claim unless appropriate resource-matched comparator supports it. Candidate higher success than a baseline using at least its declared resources, all other required constraints comparable, qualifies for a comparison finding, not automatic generalization or promotion. Candidate using more tokens but less elapsed time: declare incomparable in vector dimensions unless protocol explicitly sets shared ceilings or frontier policy. Null usage is unknown, never zero; mismatched units or unmetered provider reasoning need explicit unknown.

  3. Independent sampled arm must have no peer communication, fresh contexts and declared aggregation; verify trace edges, not model self-report. Keep aggregation cost. Positive control with complementary evidence is a separate experiment with evidence-access labels, placebo or noncommunication comparator; do not pool with shared-evidence outcomes.

  4. Retry, interrupted execution, duplicate run IDs: retain attempt lineage, count incurred compute, no duplicate scored trials. Infrastructure/verifier failure is unscored by existing taxonomy, not successful coordination or zero spend. Freeze held-out split and never auto-promote based on this report alone.

  5. Report per-task outcome and per-dimension budget, observed resource vector, comparison eligibility, uncertainty/paired sample counts and trace refs; positive and negative results retained. Existing run parity remains appropriate for strict same-config comparisons. Deterministic mock fixtures for decision logic; opt-in actual model runs only for empirical claims.

Implementation investigation

Extend existing eval matrix/research protocol or a small comparison report function, reuse gastronomic trial assembly and budget ledger. Avoid a second task runner. Decide how provider-hidden reasoning tokens, cached vs uncached tokens, parallel wall time, monetary and compute units are represented; PACE dimensions are guidance, not required identical fields. Use actual token counts with documented semantics and missing values; system constraints separate from additive quantities. Inspect current story fixtures and canonical requirements map before promotion, extend Fangore/taloneth as appropriate. June can link its JN-WF-01 to this dossier after adoption. Source experiments and local test suites not run; no native story fixture added or production code changed.
