AI assistant project host-friction inspiration

Asks from an AI assistant host for a more readable MechaHarness host surface and for graph-visible tool loops / nested recipes. This is attribution and product context, not the normative library contract.

Do not name or link private host repositories from this tree.

Normative requirements: Dynamic tool graph and node components.

Kind catalog: Node components.

Requirements map: AI assistant host-friction requirements map.

Provenance

Host documents (private; summarized here, not linked):

  • Host-friction ledger (HF-* ids)

  • Dynamic tool-graph requirements for conversational loops / recipe-as-tool

  • Interactive chat / console requirements blocked on MechaHarness surfaces

Floor at intake: mechaharness 0.4.0 (host kit + Agentic Recipes).

Vocabulary

Term

Meaning

Graph node

Established GraphNode in an ExecutionGraph

Node component

Sub-node element that must render within its parent graph node

Node-component kinds are projections of existing MechaHarness surfaces (events, soft points, nest, budget, effects). Do not invent viz-only kinds.

Ownership

MechaHarness owns: graph topology, node-component query + traversal contract, host_graph_executor event tap, Agentic Recipe conversational_tool_loop, recipe-as-tool nest via subgraph.

AI assistant host owns: web console (world / viewport), channel adapters, media / document backends, product bind of chat surfaces, deletion of parallel phase / mirror paint paths after consuming MechaHarness.
