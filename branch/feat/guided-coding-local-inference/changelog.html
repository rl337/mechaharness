Changelog

All notable changes to this project are documented in this file.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

[Unreleased]

Added

  • Coding write gutting guard: CodingWriteGuard on project-coding write_file refuses catastrophic shrink / syntax-breaking / def-dropping overwrites of existing files. verify_runs gains min_bytes and python_parses. Story fangore_coding_write_guard.

  • HTTP GitHub client (PR + CI logs): HttpGitHubClient / GitHubConnectionConfig (MECHA_GITHUB_* / GITHUB_TOKEN, not Settings) for pull requests, check runs, and job logs. Tools ci_checks / ci_job_log. LocalGitHttpPullRequestCodingGit when a token is bound. RecordingGitHubClient + story fangore_coding_ci_diagnose (coding_github: local_mock_ci) for forge lookup without network; repair remains fangore_coding_ci_repair.

  • Static-check repair lane: verify_runs accepts ruff / mypy rows. Story fangore_coding_static_checks seeds I001 / no-untyped-def and repairs under guided coding. Fixture suite sources/ trees are ignored by root pytest collection.

  • Injectable CodingGit for project coding: ABC mechaharness.coding_git.CodingGit with default LocalProcessCodingGit (local git / gh, SSH agent) and RecordingPullRequestCodingGit (local git + mock forge) for stories/CI. Hosts override via ProjectCodingConfig(coding_git=…) / get_coding_git() for HTTPS+token or forge-API backends. Tool names stay git_status / git_log / git_diff / git_push / create_pull_request. Stories fangore_coding_git_inspect / fangore_coding_git_open_pr seed a feature branch and keep GitHub mocked.

  • Sequential calc_cli coding suite (live-capable): ordered Fangore arc that grows a shared-workspace calc.py CLI through numbers → +− → ×÷ → ^ → parentheses → common functions. Suite injects environment.workspace: suite. Static CI uses coding_write stubs; live (MECHA_STORY_BACKEND=live) ignores stubs and drives ProjectCodingLocalWork with a real Completer via completer_as_tool_loop_complete. Coding bursts honor verify_runs (file text_contains plus python calc.py … checks, with one repair/refinement nudge), recover when the model finishes without write_file, and pass MECHA_MAX_TOKENS into completions. Goals require named def evaluate / def main. project_coding walks are live-eligible; the suite harness asserts live HTTP POSTs occurred. Authoring: scripts/write_calc_cli_suite.py + suites/calc_cli/sources/.

  • Sequential suite run ids: each sequential suite attempt gets a durable run_id under .mechaharness/suite_runs/ (workspace + manifest). Banner / warning / LATEST make the id easy to find; MECHA_SUITE_RUN_ID + MECHA_SUITE_FROM resume or rerun from a stage without redoing priors.

  • counter_pkg coding-delegate suite: sequential multi-file arc (package + pytest + CLI) with coding_writes stubs, verify_runs.pytest, and the same live Completer / repair path as calc_cli. Roadmap: docs/plans/coding-delegate-suites.md.

  • delegate_pkg coding-delegate suite: one sequential Widget arc covering list-mode bootstrap, thorough guidance fork (code + README), red-green double(), and Widget→Gadget refactor. Live Completer is the gate; static stubs provisional. MCP reuses the same graph (no fourth suite). Authoring: scripts/write_delegate_pkg_suite.py.

  • User-story suites: thematic suite.json catalogs under static/fixture/v1/suites/ with execution.mode parallel | sequential, vars / setup / cleanup, and explicit stages (story + scenario). Every static scenario is in exactly one primary suite. Pytest test_user_story_suite; static suite members leave test_user_story (HTTP twins remain there). Schema: tests/stories/suite_spec.py; membership helper scripts/generate_user_story_suites.py. Guide Suites section regenerated from fixtures.

  • Workspace verify verbs: run_python and workspace_read put stdout / stderr / exit_code or exists / text into the step observation bag for ordinary expects. ProjectCodingLocalWork records written_files / workspace_root on completed yields. Story environment.workspace / local_work: project_coding / coding_write bind a temp coding host. Durable + coding local work share the CLI EventLog so stories can pin core:graph_yield / core:guidance_resume / graph lifecycle via tapped_event_types. Scenario: fangore_guided_coding_recipe helper_run_python.yaml.

  • Story observation paths + plan classify: CLI expect key resolves dotted / indexed paths (plan.items[0].instruction). Durable step observations lift allowlisted yield payload fields (context_version, mode, plan, result, error). PlanClassifyLocalWork and environment.local_work: plan_classify run classify/refine offline without a coding tool loop. Story scenarios: oneshot_from_goal, numbered_list, conflict_list_refinement, explicit_list_mode.

  • MCP progress paths: tools/call with _meta.progressToken emits notifications/progress messages such as guided_coding › plan_tile › work_item 1 › tool_round 2 › write_file during generator local work (keeps Cursor stdio idle timeout alive).

  • Instruction todo plan (instruction_todo_plan): classify oneshot vs ordered list, refine conflicts, pre / per-item / post-list acceptance. Optional scope_refinement / list_refinement guidance is requested by local work (request_guidance); answering restarts the plan. Domain mechaharness.instruction_plan. Story: fangore_instruction_todo_plan.

  • Guided coding Agentic Recipe (guided_coding): frontier MCP guidance soft point tiles instruction_todo_plan (plan_tile) + audited_infer_accept (audit_tile). Host Config ProjectCodingConfig registers workspace coding tools and a GeneratorLocalWork burst after guidance. MCP MECHA_MCP_HOST=project_coding binds that Config; inference endpoints belong on the Cursor MCP env block. Story: fangore_guided_coding_recipe.

  • Audited infer-accept (audited_infer_accept): RDG-aligned spine collect → freeze → decide → independent QA → deterministic → gate, lifted from FOLK ideation.infer.accept for library reuse. Domain module mechaharness.audited_decision. Migration notes: docs/inspiration/folk-audited-infer-migration.md. Story: fangore_audited_infer_accept.

Changed

  • Live story mode collects HTTP twins and static infer / judge / judge_route walks against real reason + judge hosts; cassette-exact token counts are soft while behavioral expects stay hard. Aligns two JEV fixtures with live Laya classifications.

  • Docs: mark JobLaneBroker / stepped RunControl as shipped in architecture and DI guides; align judge / openai-local / CLI-universe live-suite notes with expanded live story collection (#32 / #33).

Added

  • Stepped graph execution (SG-01..10): RunControl on GraphExecutor.run (one_step / until / paused); soft subgraph enter-before-first-child; product verb graph_walk; graph.inline on user_story YAML. Owns fangore_graph_until_before, fangore_graph_one_step, fangore_graph_soft_enter; migrates fangore_insp_effect_revalidation.

  • JobLaneBroker (JL-01..10): lane-scoped run sequences, WalkBags, exposure / grants / handoff, and authorized observe (mechaharness.job_lane_broker). Matrix stories fangore_job_lane_*; fangore_insp_cross_task_isolation retargeted. CrossTaskIsolationGuard remains as a deprecated shim.

  • Product CLI verb transactional_resume: crash-window durable coding-job resume via host_graph_executor + ArmedCrashProbe (DR-10). Wave 2 P1 stories (fangore_tdr_crash_*) migrate onto kind: user_story.

  • Product CLI verb judge: judge-lane twin of infer (typed questions over state via JudgeProvider + cassette/live). JEV citation / route / safety / requirements stories walk this verb with real inputs.

  • Agentic Recipe context_pack: host RagRetriever → assemble_context_within_budget (fixture retriever for stories).

  • Product CLI verb tool_lifecycle: Config-bound lifecycle extensions on tool-loop or tiny graph (replaces lifecycle_case).

  • Product CLI verb assemble_context: thin pack leaf for already-scored candidate lists.

  • decision_plane execute: decision_plane_runner + DecisionPlaneRecipeAdapter (run_recipe). Restores fangore_decision_plane_{projection,policy,shadow,telemetry} and promotes recipe / model_policy stories off instantiate-only (G0).

  • verify_repair / bounded_retry execute: fixture runners + VerifyRepairRecipeAdapter / BoundedRetryRecipeAdapter promote those stories to run_recipe outcome walks (G1 batch 1).

  • fangore_bounded_repair_loop: migrated from bounded_repair_loop probe onto verify_repair run_recipe (G1 batch 2).

  • independent_review execute: independent_review_runner + IndependentReviewRecipeAdapter promote inspiration + JEV shape stories (G1 batch 3).

  • environment_repair / initialize_preflight execute: fixture runners + adapters promote those stories to run_recipe (G1 batch 4).

  • produce_critique_refine / safety_eval execute: fixture runners + adapters complete G1 control-recipe promotion (G1 batch 5).

Removed

  • Case-bag verbs decision_case and lifecycle_case: replaced by instrumented judge / context_pack / tool_lifecycle / instantiate_recipe walks (Wave 3).

Changed

  • User-story litmus (recipe expansion): missing graph path ⇒ add Agentic Recipe / runners, do not demote valid persona claims. Wave 3 demotion of fangore_decision_plane_{projection,policy,shadow,telemetry} retracted — restore under G0 (recipe expansion guide). Remaining probe batches regrouped as G0–G7 (recipe-first), not thin-verb then YAML.

  • Story harness redesign: story.json kind is now a reusable harness family (pure_api, access_authority, graph_execution, …) under tests/stories/harness/; request.json requires op for the surface within that family. New acceptance coverage should be fixtures-only by default — register a new op or harness only when the execution shape changes, never a per-story kind. Catalog validation rejects unknown kinds/ops.

  • Unit tests table-driven where cheap: test_api_connection, access-policy / grant-key matrices, tool-phase effect matrix (assert + registry in one loop), event query filters, and recipe evolvable-allowlist cases use @parametrize over structs instead of near-clone functions.

  • Alerts, correction debt, conflict checkpoints (phase 4): AlertEscalationPolicy (once/log → repeated/surface → persistent/propose, deterministic); SpecificationDebtRecord / SpecificationDebtLedger / capture_correction (schema only; hosts generate tests) with optional PromotionRecord.record_id; decision_conflict_checkpoint neighbor-revisit helpers over concurrent_write_conflicts (no second CR engine).

[0.5.0] — 2026-10-18

pyiv 1.1 HTTP + stdlib DI cut (#30). Manual minor after a squash merge auto-bumped the tip to 0.4.2.

Changed

  • Floor pyiv ≥ 1.1.0. Register use-case stdlib injectables on MechaHarnessConfig (Environment, DateTimeService, Filesystem, Clock, LoggerFactory) and route high-residue edges through them: judge from_env, checkpoint stamps, LoggingEventLog, decision JSONL.

  • Inference and judge HTTP use injectable AsyncHttpClient (AsyncUrllibHttpClient by default; MemoryAsyncHttpClient in tests) instead of raw httpx. Dropped runtime httpx; keep it as a dev extra for FastAPI/Starlette TestClient (tests/test_api.py).

  • Shared services bind in configure() and are consumed by constructor injection / inject(T). Removed Config getattr service caches and sibling get_* collaborator pulls (EventLog, AccessControl, judge connection, CheckpointStore, LinkageResolver, …). Missing bindings fail at inject time.

  • Domain ctors require injectables (no silent OS/stdlib/HTTP defaults): DecisionLog, GraphStore, LoggingEventLog, checkpoint DateTimeService, SimpleHttpConnectionConfig.from_env / for_judge(env=…), OpenAI/Anthropic/SystemOne AsyncHttpClient.

  • Normative docs: docs/requirements/dependency-injection.md; di-first rule and di-config-ownership skill updated.

Migration

  • Subclass Config (or use run() / host kit); do not hand-wire services via Config getters as a locator.

  • Pass Environment / Filesystem / DateTimeService / AsyncHttpClient explicitly in tests, or bind Memory*/Mock* doubles through Config / pyiv.override (tests/support/stdlib_doubles.py).
