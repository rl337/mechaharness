June host-friction inspiration

June-sourced asks for a more readable MechaHarness host surface and for graph-visible tool loops / nested recipes. This is attribution and product context, not the normative library contract.

Normative requirements: Dynamic tool graph and node components.

Kind catalog: Node components.

Requirements map: June host-friction requirements map.

Provenance

June documents (host repo, not this tree):

  • docs/requirements/mechaharness-host-friction.md — HF ledger

  • docs/requirements/mechaharness-dynamic-tool-graph.md — HF-07 / HF-08

  • docs/requirements/interactive-chat-channels.md — console blocked on MH

Floor at intake: mechaharness 0.4.0 (host kit + Agentic Recipes).

Vocabulary

Term

Meaning

Graph node

Established GraphNode in an ExecutionGraph

Node component

Sub-node element that must render within its parent graph node

Node-component kinds are projections of existing MechaHarness surfaces (events, soft points, nest, budget, effects). Do not invent viz-only kinds.

Ownership

MechaHarness owns: graph topology, node-component query + traversal contract, host_graph_executor event tap, Agentic Recipe conversational_tool_loop, recipe-as-tool nest via subgraph.

June owns: web console (WorldGraph / GraphViewport), channel adapters, Comfy / DocumentStore, product bind of june.chat, deletion of parallel on_phase / imagegen_mirror paint paths after consuming MH.
